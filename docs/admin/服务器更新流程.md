# 服务器更新流程

> 适用于已按 `部署流程.md` 完成首次初始化（Nginx + Git + Dart + chip_server systemd）之后的**日常更新**。
> 项目与芯片数据通过 Git 发布到 `/opt/chip_server/repo`；前端静态仍上传到 `build/web`。

---

## 一、一键更新（⭐推荐）

本地项目根目录的 `update_serve.py` 已封装全部步骤：

```powershell
# 前端 + 后端 全量更新
python update_serve.py

# 只更新前端（改了 UI / 逻辑，没动后端）
python update_serve.py --frontend-only

# 只更新后端（改了 tool/chip_server）
python update_serve.py --backend-only

# 跳过 flutter build，用已有的 build/web
python update_serve.py --skip-build
```

脚本做的事：
1. 检查 `assets/data/chips` 无未提交改动，运行 `python tool/chip_data_check.py`。
2. 执行 `git push server HEAD:main`；没有 `server` 远端时按脚本中的 SSH 配置自动添加。
3. `flutter build web --release --no-web-resources-cdn --no-tree-shake-icons --pwa-strategy=none`。
4. 清空并上传 `build/web/*` 到 `/var/www/flutter_web/`（删除 `*.map`）。
5. 在 `/opt/chip_server/repo/tool/chip_server` 执行 `dart pub get` 与 `dart compile exe`，再重启服务。

`--frontend-only` 不推送仓库，也不更新后端。Git 非快进推送被拒绝时，不要强制推送；先运行
`python sync_from_server.py` 合并服务器上的 admin 提交，再重新发布。

## 二、手动更新前端（4 步，便于排错）

### 1️⃣ 本地构建

```bash
flutter build web --release --no-tree-shake-icons --pwa-strategy=none
```

### 2️⃣ 上传（覆盖旧版本，只传内容不多套一层）

服务器侧先确保可写并清空：

```bash
ssh mingyuanli@172.25.10.143 \
  "sudo chown -R mingyuanli:mingyuanli /var/www/flutter_web && rm -rf /var/www/flutter_web/*"
```

本地上传（注意 `/*` 与目标末尾 `/`）：

```bash
scp -r build/web/* mingyuanli@172.25.10.143:/var/www/flutter_web/
```

> 📌 `build/web/*` 很重要，否则会在目标里多套一层 `web/` 目录。

### 3️⃣ 清理 sourcemap（可选）

```bash
ssh mingyuanli@172.25.10.143 'sudo find /var/www/flutter_web -name "*.map" -delete'
```

### 4️⃣ 刷新浏览器

- **不需要重启 Nginx**。
- 有缓存时 `Ctrl + F5`，或无痕窗口验证。

## 三、手动更新后端

```bash
# 1) 本地发布仓库（先提交全部芯片数据改动）
git push server HEAD:main

# 2) 服务器从仓库编译并重启
ssh mingyuanli@172.25.10.143 '
  set -e
  cd /opt/chip_server/repo/tool/chip_server
  dart pub get
  dart compile exe bin/server.dart -o /opt/chip_server/chip_server
  sudo systemctl restart chip_server
  sudo systemctl --no-pager status chip_server | head -n 12
'
```

后端源码和芯片数据均不再通过 scp 上传。推送被拒绝时先同步服务器提交，不要强制推送。

## 四、数据回流（线上 admin 编辑 → 同步回本地仓库）

线上 admin 的 Save 会写入 `/opt/chip_server/repo/assets/data/chips/`，并自动创建 Git 提交。
在项目根目录主动同步这些提交：

```powershell
python sync_from_server.py            # 获取并合并 server/main
python sync_from_server.py --dry-run  # 只查看新提交与文件统计
```

同步前须先提交本地芯片改动；合并冲突时按脚本提示在编辑器中解决，再运行
`python sync_from_server.py --check` 校验。不要再用 scp 整目录覆盖本地数据。

## 五、一次性迁移到 Git 数据架构

1. 通知管理员暂停编辑。
2. 在本地新分支用**升级前旧版脚本**最后一次拉回线上数据，检查、提交并合回 `main`：

   ```powershell
   git switch -c migrate/server-data
   python update_serve.py --pull-data
   git diff main
   git add assets/data/chips
   git commit -m "Migrate server chip data"
   git switch main
   git merge migrate/server-data
   ```

3. 服务器安装 Git 并初始化接收仓库：

   ```bash
   sudo apt install -y git
   git init /opt/chip_server/repo
   git -C /opt/chip_server/repo config receive.denyCurrentBranch updateInstead
   ```

4. 本地添加远端并推送：

   ```powershell
   git remote add server ssh://mingyuanli@172.25.10.143/opt/chip_server/repo
   git push server main
   ```

5. 保留旧数据目录：`sudo mv /opt/chip_server/assets /opt/chip_server/assets.bak-$(date +%F)`。
6. 使用新版脚本执行 `python update_serve.py --backend-only`，更新 systemd、编译并重启。
7. 在 admin 修改一个字段并保存，服务器执行 `git -C /opt/chip_server/repo log -1` 确认产生提交后恢复编辑。

## 六、常见问题

### 1️⃣ admin Save 报「后端不可达」
后端没起或反代没通：
```bash
sudo systemctl status chip_server
curl http://127.0.0.1:8088/api/chips      # 服务器本机直连后端
curl http://172.25.10.143:5174/api/chips   # 经 Nginx 反代
```

### 2️⃣ 改了后端但没生效
确认重新编译并重启：`dart compile exe ... && sudo systemctl restart chip_server`。
看日志：`sudo journalctl -u chip_server -n 50 --no-pager`。

### 3️⃣ 图标显示不完全
旧字体缓存。Nginx 已对 `/assets/fonts/` 关缓存（见部署流程.md）；
浏览器侧 DevTools → Network 勾 `Disable cache` → Application → `Clear site data` → 重开页面。

### 4️⃣ 前端更新后页面还是旧的
`Ctrl + F5` 强刷，或无痕窗口验证。`pwa-strategy=none` 已避免 Service Worker 缓存顽固问题。

---

### 👍 推荐节奏

- 日常只改 UI/逻辑 → `python update_serve.py --frontend-only`
- 改了后端 → `python update_serve.py --backend-only`
- 大版本 → 先同步服务器提交，再运行 `python update_serve.py`
