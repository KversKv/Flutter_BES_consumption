# 服务器更新流程

> 适用于已按 `部署流程.md` 完成首次初始化（Nginx + Dart + chip_server systemd）之后的**日常更新**。
> 更新分两部分：**前端静态**（build/web）与**后端服务**（chip_server）。

---

## 一、一键更新（⭐推荐）

本地项目根目录的 `update_serve.py` 已封装全部步骤：

```powershell
# 前端 + 后端 全量更新
python update_serve.py

# 只更新前端（改了 UI / 逻辑，没动后端）
python update_serve.py --frontend-only

# 只更新后端（改了 tool/chip_server）
python update_serve.py --backend-only

# 跳过 flutter build，用已有的 build/web
python update_serve.py --skip-build
```

脚本做的事：
1. `flutter build web --release --no-tree-shake-icons --pwa-strategy=none`
2. 清空并上传 `build/web/*` 到 `/var/www/flutter_web/`（删除 `*.map`）
3. 上传 `tool/chip_server` + `assets/` 到 `/opt/chip_server/`
4. 服务器 `dart pub get` → `dart compile exe` → 重启 `chip_server` 服务

> ⚠️ **数据覆盖提示**：脚本上传 `assets/` 会**覆盖**服务器上的 `/opt/chip_server/assets/data/chips/`。
> 若线上 admin 已编辑过数据且未同步回本地，重新部署会用本地种子覆盖线上数据。
> 安全做法：部署后端前，先用 `--frontend-only` 单独更新前端；后端数据更新走「四、数据回流」。

## 二、手动更新前端（4 步，便于排错）

### 1️⃣ 本地构建

```bash
flutter build web --release --no-tree-shake-icons --pwa-strategy=none
```

### 2️⃣ 上传（覆盖旧版本，只传内容不多套一层）

服务器侧先确保可写并清空：

```bash
ssh mingyuanli@172.25.10.143 \
  "sudo chown -R mingyuanli:mingyuanli /var/www/flutter_web && rm -rf /var/www/flutter_web/*"
```

本地上传（注意 `/*` 与目标末尾 `/`）：

```bash
scp -r build/web/* mingyuanli@172.25.10.143:/var/www/flutter_web/
```

> 📌 `build/web/*` 很重要，否则会在目标里多套一层 `web/` 目录。

### 3️⃣ 清理 sourcemap（可选）

```bash
ssh mingyuanli@172.25.10.143 'sudo find /var/www/flutter_web -name "*.map" -delete'
```

### 4️⃣ 刷新浏览器

- **不需要重启 Nginx**。
- 有缓存时 `Ctrl + F5`，或无痕窗口验证。

## 三、手动更新后端

```bash
# 1) 上传源码 + assets（首次或后端代码有改动时）
scp -r tool/chip_server/pubspec.yaml tool/chip_server/bin mingyuanli@172.25.10.143:/opt/chip_server/

# 2) 服务器编译并重启
ssh mingyuanli@172.25.10.143 '
  set -e
  cd /opt/chip_server
  dart pub get
  dart compile exe bin/server.dart -o chip_server
  sudo systemctl restart chip_server
  sudo systemctl --no-pager status chip_server | head -n 12
'
```

> 后端只改了代码、**不想动线上 JSON 数据**时，**不要**上传 `assets/`。

## 四、数据回流（线上 admin 编辑 → 同步回本地仓库）

线上 admin 的 Save 会写到服务器 `/opt/chip_server/assets/data/chips/`。
若要把线上编辑的数据同步回本地 git 仓库（避免下次部署被覆盖）：

```bash
# 从服务器拉回 chips 数据到本地（在项目根执行）
scp -r mingyuanli@172.25.10.143:/opt/chip_server/assets/data/chips/* assets/data/chips/
```

随后本地 `git diff` 检查、提交即可。

## 五、常见问题

### 1️⃣ admin Save 报「后端不可达」
后端没起或反代没通：
```bash
sudo systemctl status chip_server
curl http://127.0.0.1:8088/api/chips      # 服务器本机直连后端
curl http://172.25.10.143:5174/api/chips   # 经 Nginx 反代
```

### 2️⃣ 改了后端但没生效
确认重新编译并重启：`dart compile exe ... && sudo systemctl restart chip_server`。
看日志：`sudo journalctl -u chip_server -n 50 --no-pager`。

### 3️⃣ 图标显示不完全
旧字体缓存。Nginx 已对 `/assets/fonts/` 关缓存（见部署流程.md）；
浏览器侧 DevTools → Network 勾 `Disable cache` → Application → `Clear site data` → 重开页面。

### 4️⃣ 前端更新后页面还是旧的
`Ctrl + F5` 强刷，或无痕窗口验证。`pwa-strategy=none` 已避免 Service Worker 缓存顽固问题。

---

### 👍 推荐节奏

- 日常只改 UI/逻辑 → `python update_serve.py --frontend-only`
- 改了后端 → `python update_serve.py --backend-only`
- 大版本 → `python update_serve.py`（注意「一」的数据覆盖提示）
